# Vesper: rules for working on this repo

Vesper is a single file PWA chat app (`index.html`) served by GitHub Pages from `main`. No backend, no build step, no accounts, no analytics. Keys and chats live only in the browser's localStorage under `vesper.v1`.

## Owner's standing rules
- Free only. No paid services or paid dependencies (this is why fonts and scripts are self hosted in `fonts/` and `vendor/`).
- Settings is always shown with the real gear icon: the Lucide `settings` gear, symbol `#i-settings`. Never a sun, dial, sliders or any other icon for Settings.
- Fonts: Inter (standard AI app sans). No serif fonts anywhere, and no monospace for labels (monospace only inside code).
- No dashes in written copy: no hyphens between words and no en or em dashes, in the app, README or images. Short, direct wording.
- Neutral wording. No "roleplay" or "uncensored" wording anywhere. The owner wants Characters (custom personalities, shown as "Characters"; the code still calls them companions) and a hidden adult option, named neutrally: "Characters" and "Open conversation" (Settings, Personalize, More options; no pop up). The open option only removes disclaimers and allows mature themes for adults; never write prompts meant to defeat a provider's safety rules, and never allow sexual content involving minors.
- Never commit or paste API keys.
- Design: pure black, quiet, premium, Grok like feel but original. Accent blue `#6ea8ff`. The logo is five curved chrome blades around a star shaped opening: `icons/chrome/mark.webp` (3D), `icons/logo.svg` (flat), source in `design/logo/`.
- Ships as a PWA (the owner cannot sideload APKs).
- Screenshots for the README, stores or promos are never plain captures: always the edited, premium SaaS style art (dark backdrop, headline and short line of text, screen in a frame), like the README images from `docs/art/make-art.js`.
- Desktop look: on wide screens and in the Windows app the sidebar stays docked on the left (`body.dock`, `applyDock()`), like a desktop chat app, never a stretched phone layout. Default theme is pure black with no wallpaper (`none`); never make a textured wallpaper the default.

## How the UI works
- Every panel (drawer, bottom sheet, full screen page, dialog) is a layer opened with `open(id, factory, swap)` and closed with `closeTop()` or `closeAll()`. Layers sit in one stack mirrored in browser history, so Android back closes the top one.
- Characters, Learn (including each guide) and Studio (Create) are full screen pages. `makePage(title, render, {full:true})` forces the full screen layout even when the page is opened from a modal or on a docked desktop. Never render these as the centered modal card.
- A layer ignores taps while it slides in (`.settling`) and the moment it starts closing. Opens requested during a close wait in a queue. Keep this, it fixes taps landing on the wrong thing.
- App icon finishes: `ICONS` in index.html. Chrome uses `icons/chrome/` and `manifest.webmanifest`; each other finish has `icons/<id>/` (icons, mark, preview) and `manifest-<id>.webmanifest`. All manifests share `"id": "./"` so switching never makes a second app. Render new finishes with `design/logo/r3d.html` (tint, glow, mid, base, rim params).
- Each app icon finish also themes the app: `applyIcon()` sets --accent, --surface, --raised, --line and --glow from `ICONS`.
- Memory: the model ends a reply with `[[remember: fact]]` when it learns something lasting (see MEMORY_RULE). `generate()` strips the tag, saves to `S.memory`, and `systemPrompt()` sends saved facts with every chat. Private chats never save.
- Characters live in `S.companions` (`CHAR_LIBRARY` holds the ready ones, matched by `pid`, with portraits in `chars/<pid>.webp`; only these get the Verified by Vesper badge, and their profile says AI; optional `facts` (age, birthday, zodiac, likes, dislikes, interests, bond, memories) are sent once in the system prompt by `companionPrompt()` and shown on the profile); a chat with `companion` set uses `companionPrompt()` instead of the Vesper prompt.
- Freeform models (open models with no added guardrails) are `PC_OPEN` and `OPEN_MODELS`. Always word them professionally: "Freeform", "no added guardrails". Never "uncensored".
- Attachments: photos are shrunk to 1024 px JPEG and sent as image_url parts; text files are inlined as text (`toApi()`).
- Learn: guides live in `LEARN` in index.html, screens in `learn/*.jpg` made by `node docs/art/make-art.js`. Brand logos come from Simple Icons (CC0) in `BRANDS`; brands without a free logo (OpenAI, Groq, Cerebras) get a name badge in `BADGES`, never an imitation.
- Chat wallpapers: `CHAT_BGS` are repeating SVG doodle patterns built by `pattern()`, or the user's photo. They paint the whole chat screen (`#app`) behind a glass header and composer; light ones switch the chat to `.lightwall`.
- Look and feel: a professional, trustworthy desktop app (the owner's reference is the Claude desktop Settings window). Appearance has Theme and Display scale (75 to 150%, 100% recommended and the default; on wide screens 100% is drawn at 0.87 zoom via `DESK_BASE`, so the app reads like a normal desktop app), each a dropdown (`dropdown()`), applied by `applyAccent()`. Themes (`THEMES`) are named, never shown as color dots or swatches, and the setting is called Theme, never color: Classic (Midnight, the default pure black, and Graphite) and Gradient themes that tint the whole app like Discord's (Deep Ocean, Alpine, Twilight, Ember, Sakura, Titanium), each with its accent and gradient (`--accent`, `--grad`, body `tinted`). Settings keeps every section in the left menu. Provider and model rows render inline in the right pane through `settingsGo()` and `settingsNavApi`, so no layer opens over Settings. The profile (`S.profile`: name, call, work, photo or `mark`) shows in the sidebar footer and is sent in `systemPrompt`; avatars are an uploaded photo (cropped to 256 px) or one of the exclusive avatars made from the logo finishes in `ICONS` (`pickAvatar`). Check alignment every time anything visual changes: measure that icons, text and controls in a row share one center line (the composer controls are all 40 px tall for this). App icon finishes and chat wallpapers are no longer offered in Settings; do not add more theme options. The two tabs are plain icons and labels in the left menu. Clicking a tab or any row inside Settings redraws only the right pane; no sheet, page or dialog opens on top of Settings. Models is the only place to add models: Choose a model, Cloud providers, Local models, Add a local model, Manage models and Find your model all render inline in that pane. Use `inlineLayer()` and pass `{into, nav}` to `openProviders()`, `openProvider()`, `openLocal()`, `openConn()` and `manageModels()` to keep their existing logic without a new layer. Headings and rows stay flat: label left, control right, thin lines. All surfaces use the same theme variables, with no extra overlay color: modals and dialogs use `--sheet` or `--surface`, not hard coded backgrounds.
- The full Settings menu is restored. Keep every section listed in `docs/SETTINGS_HANDOFF.md`. Provider and model rows use `settingsGo()` so they redraw the right pane instead of opening a layer over Settings. `S.spell`, `S.wrap`, `S.calm`, `S.pinch`, `S.mono`, `S.tlLevel`, `S.tlShow`, `S.tlWidth`, `S.bgActivity`, `S.notify`, `S.sound`, `S.wake`, `S.groupChats`, `S.sideOrder` and `S.ideas` keep their behavior in chat and boot code.
- Details panel (`#insp`, wide screens, Ctrl+I or the panel button in the header): the model in use (where it runs, context window, reply limit, creativity), live activity while it works (`act`: phase, elapsed, first word, speed, time left at most, the thinking text) and tokens for the last reply and the chat. Exact token counts come from `usage` when the provider sends it (`stream_options.include_usage` for OpenRouter, Groq, Cerebras and this PC); otherwise they are estimates and say so. Each reply stores `stats`.
- Desktop motion (wide screens and the Windows app): it must feel like the Claude, ChatGPT and Gemini desktop apps, never like a web page. Menus (`menu()`) open as small popovers anchored to the button that opened them, dialogs and the Settings window fade in with a slight scale, pages fade in place (no sliding, no bottom sheets, no big drops); `--d` is 160 ms on desktop. Every screen, Support included, uses these same building blocks. The profile photo button opens a popover (Upload photo, Choose an avatar, Remove); Choose an avatar is our own layout (never a honeycomb or any other app's picker): a large live preview on top, an even 8 column grid of 24 avatars below, and New set, Cancel and Save, saved as `S.profile.gen`. Avatars are our proprietary Vesper rosette style: curved blades around an open center, like the blades of our logo, generated from a random seed (`avShape`: blade count 3 to 7, twist, size, rotation) in white on a soft two tone gradient of one of `AV_COLORS`. Never copy another app's avatar glyphs. With no photo or avatar chosen, the default is the Vesper mark, never a letter.
- Icons are Phosphor (MIT, regular weight, `viewBox 0 0 256 256`, fill) in the SVG sprite, except Settings which stays the Lucide gear. Vesper Plus is removed from the app for now; do not bring it back unless the owner asks.
- Local AI first: on Windows the home screen shows `setupCard()` until a model is on the PC: it reads the PC (`pcSpecs`), picks the best fit with `adviseModels`, and Install and start downloads it with a progress bar, selects it and starts the engine (`pcSetup`). Next planned feature: a coding agent mode (open a folder, read and edit files, run commands) in the Windows app.
- Home screen stays minimal: a heading and the composer (plus the idea list once a model is ready); with no model on the web only Connect a model and Use a local model as two small buttons. No big logo, no extra links. The header stays pinned at the top, and the details panel button shows only once a chat has messages.
- Workspaces: a Chat / Agent / Code switch at the top of the sidebar (`SPACES`, `setSpace()`, Ctrl+1/2/3, `body[data-space]`). All three share the chat thread and the same composer. The right panel changes with the space. Agent has a goal card, a collapsible mind map of steps and a collapsible timeline in the right panel; `S.agent.steps` holds steps with status, note, time and parent. Ask for a plan sends a prompt to the chat and parses numbered lines back into steps, and never claims tools ran. Code has a real local editor in the right panel with file tabs, line numbers, New file, Rename, Copy, Download, Ask Vesper and Delete; `S.codeFiles` and `S.codeActive` hold the files. Every code block in a reply has an Open in editor button through `decorate()` and `openCodeBlock()`. Both panels collapse with `toggleSpacePanel()` and `S.spaceCollapsed`. See `docs/WORKSPACES_HANDOFF.md` for the layout contract and checks. The layout follows the Claude desktop app: a collapsible left sidebar (collapsed it stays as a 64 px icon rail with the expand button, never fully hidden; `body.dock.side-off`) and a collapsible right panel (`#insp`: model, Context percent with a small bar, activity, this chat, last reply, Connectors, Outputs from the Library). Clicking the chat title opens the chat menu. The right panel is a general tab system: horizontal tabs (`pTabs`, `openPanelTab({id, title, icon, render})`, `closePanelTab`), Details always first, other tabs closable; Preview (`previewMedia`) opens outputs in a tab, and Phase 2 adds the code editor, browser and logins as tabs the same way. Drag the panel's left edge to resize it (`inspDrag`, `S.inspW`, 280 px up to 60% of the window).
- Desktop chat app layout (wide screens and the Windows app): our own desktop chat app layout, inspired by Grok and ChatGPT but never a copy: sidebar with logo, search and hide buttons, New chat (with its Ctrl N hint), Characters, Learn, a Studio section, chats with Show more, and a footer status row (Local AI ready or Set up local AI on Windows, providers connected on the web) with Support and the Settings gear. An empty chat shows the greeting with the composer in the middle and ideas listed below it; the composer is always our own one line glass pill (plus, text, model, mic, send), larger on the empty chat (with the logo mark beside the greeting) and pinned at the bottom in a chat; never copy another app's composer layout (no two row box, no row of pickers under it). Settings opens as a floating window (`makePage(..., {modal:true})`, `settingsNav()`) with a section menu on the left; pages opened from it stay in that window.
- Connect apps (Settings): `APPS` lists the apps; `APP_LOGO` holds full color logos (CC0, gilbarbara logos via Iconify) shown on dark tiles (black logos are inverted), with Simple Icons paths as the fallback. Connectors are not built yet, so the button is Request / Requested (no pop up) and only saves `S.waitlist["app:<id>"]` on the device; never show a working Connect button until the connector really works.
- Studio (`openStudio`, one page for Image Studio, Video Studio and Library, inspired by Google Flow but our own design): the home has a banner with a muted looping video (`STUDIO_BANNER`; the credit shows only while the video plays; the poster and fallback is our own film style banner `studio/banner.webp`, never a stand in from elsewhere). A fresh install is empty: no sample projects or generations, only the New project card and a short note, a How it works row, and a Your projects grid starting with New project. A project opens a workspace (`studioSpace`: left rail with All media, Images, Videos and the generator, search, media grid) with a floating prompt bar (`studioBar`: an Image / Video toggle shown side by side, never a vertical menu, then the prompt, shape chip, a rounded rectangle Library button on the right, and send; the bar also shows on the Studio home and the first send makes a project). The sidebar has one Create entry, not separate Image, Video and Library entries. The Studio home has no How it works button, only the How it works row. `S.projects` holds projects and each media item has a `project` id; items without one show as Earlier creations; Library opens All media. Keep the prompt bar controls 40 px tall and on one center line.
- Create (rest): Image Studio and Video Studio are real. Images come from the generator picked in Settings, Image and video (`S.media`): Free (Pollinations, no key), Pollinations with a key, any OpenAI style images endpoint, or an OpenRouter image model with the user's key (`genImage`). Video uses a Pollinations key (`genVideo`). Everything made is saved on the device in IndexedDB (`vesper-media`) and shown in the Library (`openLibrary`). Skills (`SKILLS`, aimed at video, ads, UGC and content work, each with its own colored icon, plus `S.skills`) add instructions to one chat (`c.skill`, sent by `systemPrompt`); pick one from the plus button in the composer. Settings rows use plain icons (`rico`).
- Live Characters is removed from the product. Do not add it back to the sidebar, `LANDINGS`, README or site. The old art files (`docs/studio-live.webp`, `studio/seraphine.webp`, `studio/aurelia.webp`, `studio/scarlet.webp`) are unused and can be deleted.
- The Thinking indicator is the shimmering word only. No wave or line animation.
- Models are keyed `provider::id` (see `mk()`). Discovered models start hidden; only shown models appear in the picker.
- Local models are OpenAI compatible connections in `S.conns`. Calls to private addresses pass `targetAddressSpace` so Chrome allows them from the https page.

## Node Folds site (nodefolds/)
- Node Folds is the parent company. Its site lives in `nodefolds/` (plain HTML, CSS and JS, no libraries) and is live at https://nodefolds.com (and www, which redirects). The Cloudflare Worker `nodefolds` serves the files straight from `main` on GitHub (cached 5 minutes), so merging to `main` publishes it: no deploy step and no Netlify. `/privacy` serves `privacy.html`. `/terms` serves `terms.html`. `/support` serves `support.html`. Email: support@, privacy@ and hello@nodefolds.com forward through Cloudflare Email Routing to the owner's Gmail; use support@ for every Contact us link.
- Site layout: no scroll progress bar. The story section shows the real app (current screenshots in `img/app-*.webp`, captured full screen from the latest version with no title bar and no Live Characters) inside a tablet with no status bar, with floating chips (`.fc`) that change with each slide. The studio section shows one iPad: the real Studio home (`img/app-studio.webp`), then the real Video Studio workspace (`img/app-video.webp`) slides up inside the same iPad (made from clean cells of the studio art). There is no phone mockup on the site; do not add one. Image Studio and Video Studio are live, so never label them coming soon. The owner wants the site to look final: no status tags like In development anywhere; unfinished work (Code, Agent, built in browser, encrypted chat folders, shared memory) stays only in the Roadmap section, worded as plans, never as available. Vesper Plus does not appear on the site. Capture the app at 1100 by 764 (device pixel ratio 2) so the UI stays readable inside the tablet, and recapture whenever the app's look changes. The tablet and phone are sized by the smaller of width and height so they never squash, and each frame wraps a screen that has the exact proportions of its screenshot (`.screen{aspect-ratio}`), so nothing is cropped; after changing them, measure that the iPad stays fully inside the viewport at 1920, 1366, 1024, tablet and phone sizes. The story script only counts images inside `.story` (`shots`), so never add other `.screen img` outside it without scoping.
- The site showcases every Node Folds product: add products to `PRODUCTS` and outside links to `LINKS` in its script (an empty link hides it, except X, Reddit and GitHub which stay visible). The logo is `design/nodefolds/` (mark.svg, icon.svg, logo.png); the site icons are `img/nf-icon*`. Every outside logo (socials, Apple, Google Play, Windows, stores) is monochrome: black on white buttons, white on dark; only Node Folds, Vesper and the Google Play icon keep their color. Platform icons use the owner's brand files in `img/brand/` (Apple, Google Play, X, Reddit), never generic phone or download icons.

## Windows app (desktop/)
- Tauri 2 wraps the same web app: `desktop/scripts/copy-web.mjs` copies the site into `desktop/dist`. Native code is `desktop/src-tauri/src/lib.rs`: `system_info` (RAM, cores, GPU and VRAM via DXGI), `list_models`, `download_model` (Hugging Face only, resumable, `dl-progress` events), `cancel_download`, `delete_model`, `start_engine` (bundled llama-server on 127.0.0.1, GPU first then processor), `stop_engine`, `engine_status`. The window has no system frame: index.html draws a Windows style title bar (`#titlebar`, shown when `body.native`) with the sidebar toggle and real minimize, maximize and close buttons through the Tauri window API (permissions in `capabilities/default.json`). Shortcuts: Ctrl+N new chat, Ctrl+B sidebar, Ctrl+K search, Ctrl+, settings. On wide screens sheets open as centered dialogs. The app also sets the bundled Vesper icon on the window and has a system tray icon with Open and Quit actions. Closing the window hides it to the tray so a running local model keeps going; Quit exits cleanly.
- In index.html, `DESKTOP` is true inside the app. PC models use the connection id `pc` and keys like `pc::<file>.gguf`; `pcEnsure()` starts the engine before sending. The catalog `PC_MODELS` lists verified Hugging Face GGUF files: check new entries exist before adding them.
- `.github/workflows/desktop.yml` builds on windows-latest: it downloads the llama.cpp Vulkan build (`LLAMA_CPP_TAG`) into `desktop/src-tauri/engine/`, then `npm run build`. Pull requests get a test build; pushing a tag `desktop-vX.Y.Z` publishes a release. Bump the version in `desktop/src-tauri/tauri.conf.json`, `Cargo.toml` and `desktop/package.json` together.
- Check native code locally with `cargo check --target x86_64-pc-windows-msvc` in `desktop/src-tauri` (after `node desktop/scripts/copy-web.mjs`).

## Releasing
- Bump `CACHE` in `sw.js` on every release, or phones keep the old copy.
- For a release users should see, bump `APP_VERSION` in index.html and `version.json` together and write short notes in `version.json`: open apps show an Update available popup with those notes.
- Support page: `openSupport()` shows the live total from `https://vesper-chat.netlify.app/api/support`. `netlify/functions/kofi.mjs` is the Ko-fi webhook (POST `/api/kofi`): it checks `KOFI_TOKEN`, counts each completed payment once in Netlify Blobs; `KOFI_ADJUST` adds past support or subtracts refunds, `KOFI_GOAL` sets the goal. Payment runs in the Ko-fi panel iframe (`SUPPORT.kofi`, ko-fi.com/buymeacofi).
- Test in a phone sized Playwright run (412 by 915) before pushing.
- The live app is https://vesper.nodefolds.com (the README Try Demo link). The Cloudflare Worker `vesper` serves the app files straight from `main` on GitHub (only index.html, sw.js, version.json, the manifests and the fonts, vendor, icons, chars, studio and learn folders), so merging to `main` publishes it: no deploy step. Netlify ran out of credits; the site `vesper-chat` is kept only for the Ko-fi function (`node netlify/stage.mjs` then the Netlify MCP deploy, when credits allow).

- Menus (`menu()`): a follow up menu (Use a skill from the plus menu) keeps the original button as its anchor, opens left aligned, and above the composer when the button is in it. Skill chip sits after the plus on the composer center line.
- Full width on desktop: card pages (Learn, Characters, Library) fill the whole window (`.page-body:has(.lcards,.cgrid,.spg)`, grids auto fill), never a phone width column; the chat column and composer scale with the window (`--col`, 760 to 980 px).
- Body zoom scales vh and dvh too, so heights that fill the window are divided by `--z` (set in `applyAccent()`): `.app{height:calc(100dvh / var(--z,1))}`. Never use plain 100vh or 100dvh for window sized layout. On desktop the composer (and the Studio prompt bar) stays a rounded pill, never a full width strip, pinned at the bottom of the window with a glassy frosted look (blur, translucent surface, thin light border); messages scroll behind it.
- Settings stays the floating window with its left section menu (never a full screen page). Interface layout is a row with the title and detail at the top left and three rectangular preview cards on the right (`layoutCards()`: Docked, Rail, Focus). Picture orientation is always shown as small rectangle icons (`oriPick()`, `.ori`), never as words: in the Studio prompt bar and in Settings, Create. Focus on Windows first: the phone layout comes later, so optimise desktop and do not spend effort on mobile for now. Every setting needs a plain detail line under its name, written for people who do not know the term.
- Models and keys are added, downloaded and managed only in Settings (Providers, Models, Desktop app). Nothing else, not the home screen, the sidebar status row, the model picker or a Learn guide, adds or downloads a model: they call `toSettings(view)` which opens Settings on the right page. The model picker only switches between models already shown.
- New chat on desktop is one line of text (`.hero h1.hl`, Inter, tight tracking, soft gradient) with the composer under it; suggestions appear beneath the bar only while typing (`renderTypeSug()`, `PROMPTS` plus the user's own earlier first messages; Tab accepts, arrows pick).
- Aspect ratios (`ASPECTS`: 1:1, 16:9, 9:16, 4:3, 3:4, 3:2, 2:3, 21:9, 4:5) are chosen from a dropdown in the Studio prompt bar and in Settings, Create; `sizeFor()` turns one into pixels from the long side (`S.imgLong`). Not rectangle icons, not Square or Wide words.
- Settings are meant to be deep and technical for people who build with models: Parameters (temperature, top P, max tokens, penalties, seed, stop sequences, reasoning effort, history sent, streaming, all sent in `generate()` only when set) and Developer (reply details, copy last request as cURL or JSON, export, import and reset settings). Each row has a plain detail line.
- No oversized white block buttons on desktop: `.btn.block` is compact (`body.dock .btn.block`), primary actions sit in a page header or an empty state card (`.emptyc`), never a full width bar. Skills use a proper editor (name, instructions, icon) and a page with Yours and Built in groups.
- Settings aim for everything the big AI apps offer, as long as it really works: Voice (reading voice, speed, read replies aloud, dictation language), reply language, chat text size, high contrast, focus outlines, message time, plus Parameters and Developer.
- Settings structure (one place per thing, no filler rows, no rows that only say a feature does not exist): General, Account, Appearance, Chat, Personalization | Providers, Models, Parameters, Timeline, Create | Voice and sounds, Notifications, Shortcuts | Usage, Privacy and data, Developer | Desktop app (Windows), Help, About. Never repeat the same control in two sections, never add a section that only links to other sections, and never add a static row such as "Not used" or "Planned". Shortcuts are listed inline as key chips. Settings code uses `strCtl(key, ph)` for plain text settings and `textCtl(label, key, ph)` for profile fields: never define two functions with the same name.
- Every page inside the Settings window (sections, inline views like Providers and Local models, nested pages like Memory and Connect apps) shares one design system defined once in CSS (`settings design system` block): rounded cards of rows, `.field` blocks, compact buttons, small muted sub headings, numbered steps. New pages must use `row()`, `ctlRow()`, `group()` and `glabel()`, never one off blocks. Copy must make sense on a computer, never say phone.
- Typing / on the empty chat lists skills under the box (Tab or Enter picks one). The greeting follows the time of day and the profile name.
